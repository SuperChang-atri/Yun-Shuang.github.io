# MSB 网站维护指南（管理员版）

> 本文汇总网站所有常见维护操作。**成员自助改个人信息**请看 [成员自助维护指南.md](成员自助维护指南.md)。
> 一句话原则：**所有内容都是仓库里的文件，改文件 → 提交 → 1~2 分钟自动上线，没有后台、不需要登录任何管理系统。**

---

## 一、网站是怎么工作的（30 秒版）

- 网站 = 仓库里的一堆静态文件（HTML/CSS/JS/JSON/图片），托管在 GitHub Pages，地址 https://yun-shuang.github.io
- 你每次把修改**提交/合并到 `main` 分支**（网页上改、本地 push、合并 PR 都算），GitHub 的免费机器人（Actions）就会自动构建并发布
- 时间线：提交 → 约 10 秒机器人启动 → 约 30~60 秒构建部署 → 全球生效。**总共约 1~2 分钟**
- 查看进度：仓库页面顶部 **Actions** 标签，绿色勾 = 成功，红色叉 = 失败（会收到邮件）
- 浏览器有缓存时按 **Ctrl + F5** 强制刷新看最新版

两种改法，效果一样：

| 方式 | 适合 | 操作 |
|---|---|---|
| GitHub 网页直接改（推荐日常用） | 改文字、上传照片 | 仓库 → 点开文件 → ✏️ 编辑 / Add file 上传 → Commit changes |
| 本地改完 push | 批量改动、结构调整 | 改文件 → `git add -A && git commit -m "..." && git push` |

## 三、最新动态（news.json）

文件：`_data/news.json`，结构：

```json
{
  "items": [
    { "date": "2026-09", "text": "English text", "text_zh": "中文内容" }
  ]
}
```

- **加一条**：复制一个 `{}` 块改内容，放在数组里想要的位置（顺序 = 网页显示顺序）
- **删一条**：删掉对应 `{}` 块（注意前后逗号）
- `date` 是显示用日期，格式随意（如 `2026-09`、`Sep 2026`）
- `text` 英文、`text_zh` 中文，两个都要写

## 四、活动相册（gallery）

> 照片自动显示在**团队成员页底部的"活动掠影"轮播**（自动播放、底部圆点手动切换、鼠标悬停暂停、手机可左右滑动），无需单独维护展示。

### 加照片（最常用）

1. 网页打开仓库 → 进入 `assets/img/gallery/` → **Add file → Upload files**
2. 上传照片（建议先压缩，见下方"图片规格"）
3. 提交后机器人会自动把新照片追加进 `_data/gallery.json` 并发布，**不用改任何代码**
4.（可选）想加说明文字：打开 `_data/gallery.json`，找到对应条目填 `caption`（英文）和 `caption_zh`（中文）；文件名以日期开头（如 `2026-09-20.jpg`）时会自动填入 `date`

### 删照片

在 `assets/img/gallery/` 里删除对应文件并提交，机器人会自动移除清单条目。

### 调整顺序 / 改说明

直接编辑 `_data/gallery.json`：数组顺序 = 网页显示顺序；改 `caption` / `caption_zh` 即可。

> ⚠️ `_data/gallery.json` 的"条目增删"由机器人自动维护，你只管文件夹和说明文字；手动增删条目也会被机器人按文件夹实际情况纠正。

### 图片规格建议

- 宽度 1200~2000px，JPG/PNG/WebP，**单张 ≤ 500KB** 最佳（手机原图通常 3~15MB，务必先压缩）
- 建议横版照片（3:2 或 4:3）：轮播按 3:2 比例裁切显示，过窄或过长的图会被裁掉边缘
- Windows 压缩方法：右键照片 → 用"照片"应用打开 → 调整大小导出；或批量用美图秀秀/光影魔术手等
- 首页大合照 `group-photo.jpg` 同理（当前 2000px / 403KB）

## 五、成员信息

- 成员自助：按 [成员自助维护指南.md](成员自助维护指南.md) 提 PR，管理员审批合并后自动上线
- 管理员代改：直接编辑 `_data/members/<id>.json` 提交（就像之前添加景文凤那样）
- 成员照片：传到 `assets/people/<id>.jpg`（正方形，边长 ≥400px、≤300KB），在成员 json 里把 `photo` 填为该路径
- **不要手改 `_data/members.json`**（机器人自动生成的汇总文件）

### 权限说明

- 普通成员：**不需要任何权限**，网页提 PR 即可（GitHub 会自动 fork）
- 管理员（能审批 PR、直接提交）：仓库 **Settings → Collaborators → Add people** 邀请其 GitHub 账号（Write 权限），并把用户名加入 `.github/CODEOWNERS`（每行一个 `/_data/members/ @用户名`）

## 六、论文列表同步

- **自动**：每周一凌晨（UTC 02:00）从 OpenAlex 同步樊老师的论文、引用数、h 指数
- **手动**：仓库 → Actions → 左侧 "Sync Publications" → 右侧 "Run workflow"，几分钟后自动更新
- **失败怎么办**：机器人会邮件通知；数据源偶尔抖动，下周会自动重试；急需可联系维护者在本地跑 `python scripts/sync_publications.py` 后提交
- 数据源说明：用 OpenAlex 而非 Google Scholar，因为 Google 会拦截云端抓取（详见 README）

## 七、常见问题

**Q: 改完多久能看到？**
一般 1~2 分钟。成员/相册类改动多一步机器人自动汇总（约 +30 秒）。先在 Actions 标签确认绿色勾，再 Ctrl+F5 刷新页面。

**Q: F5 和 Ctrl+F5 有什么区别？**
- **F5**（普通刷新）：浏览器尽量用本地缓存，可能仍显示旧版本；
- **Ctrl+F5**（强制刷新，等价 Ctrl+Shift+R）：跳过浏览器本地缓存，重新下载全部文件——确认"网站更新了没有"时用它。
- 注意它只清理你自己浏览器的缓存；GitHub 的 CDN 缓存通常几分钟内也会自动更新。

**Q: 网页上找不到 ✏️ 编辑按钮？**
确认你登录的是有权限的 GitHub 账号（管理员）；普通成员请走 PR 流程（见成员指南）。

**Q: 改错了能恢复吗？**
能。Git 保存全部历史：仓库 → 文件 → History 可查看并回退任何版本。

**Q: 仓库放在 OneDrive 里有什么要注意？**
尽量避免多台电脑同时编辑；OneDrive 偶尔会"复活"刚删除的文件或锁定 .git 目录，遇到异常先刷新文件夹再操作。

**Q: 想在首页加新板块 / 大改样式？**
属于结构性修改，建议本地改完充分预览（`python -m http.server 8000`）再 push，或交给维护者处理。
