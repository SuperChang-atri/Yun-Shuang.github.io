# 成员信息自助维护指南

> 本文面向 MSB 研究组成员。你不需要会编程，全程在 GitHub 网页上点选即可完成。
> 整个流程可以概括为：**改一个文件 → 提交 Pull Request（修改申请）→ 管理员审批 → 自动上线**。

---

## 一、你需要提交什么？

| 必交 | 内容 |
|---|---|
| ✅ 必须 | `_data/members/<你的id>.json` —— 你的个人信息文件（从模板复制改名） |
| ⬜ 可选 | `assets/people/<你的id>.jpg` —— 个人照片（正方形，边长 ≥400px，≤300KB；不上传则自动显示姓名首字母头像） |

`<你的id>` 规则：**小写拼音/英文名，用连字符连接**，例如 `san-zhang`、`yihan-chen`。文件名必须和文件里的 `id` 字段一致。

## 二、操作流程（首次绑定）

> 💡 **更省事的方式**：打开 **https://yun-shuang.github.io/member-json/**，在线填表、一键下载你的 json 文件，然后从下面**第 5 步**开始操作即可。下面的手动方式适合想了解每一步细节的同学。

### 第 1 步：登录 GitHub，打开仓库

打开 https://github.com/Yun-Shuang/Yun-Shuang.github.io ，登录你的 GitHub 账号（没有就免费注册一个）。

### 第 2 步：复制模板

1. 进入 `_data/members/` 目录，点击 **`_template.json`**；
2. 点击右上角的 **复制原始内容**（或直接全选复制）。

### 第 3 步：创建你自己的信息文件

1. 回到 `_data/members/` 目录，点击右上角 **Add file → Create new file**；
2. 文件名填 **`<你的id>.json`**（如 `san-zhang.json`）；
3. 把模板内容粘贴进去，按字段说明填写（见下方"字段说明"）；
4. 没有的信息（如 GitHub、ORCID）**留空字符串 `""` 即可，不要删字段**。

### 第 4 步：（可选）上传照片

1. 进入 `assets/people/` 目录，**Add file → Upload files**；
2. 上传命名为 **`<你的id>.jpg`** 的正方形照片；
3. 然后在你的 json 文件里把 `photo` 填为 `assets/people/<你的id>.jpg`。

> **照片规格**：正方形（1:1）最佳，边长 600–800px（至少 400px），文件 ≤ 300KB，JPG 格式。
> 页面会按中心自动裁切成圆形/圆角——非正方形照片不会被拉变形，但边缘可能被裁掉，建议人脸居中、肩部以上取景。

### 第 5 步：提交 Pull Request（修改申请）

1. 页面下方 **Commit changes** 区域：标题写 `Add/Update member: 你的名字`；
2. 选择 **"Create a new branch for this commit and start a pull request"**（GitHub 对无写权限账号会自动 fork，属正常现象）；
3. 点击 **Propose changes** → 下一页点 **Create pull request**；
4. 完成！系统会自动进行格式检查（约 1 分钟，显示在 PR 页面的 Checks 里）。

### 第 6 步：等待审批

- 管理员（樊老师及指定管理员）会收到 Review 请求；
- 若格式检查不通过或信息有误，管理员会在 PR 里留言，你按提示在原分支上继续修改即可（改动会自动同步到同一个 PR）；
- **审批合并后约 1–2 分钟，网站自动更新，无需任何其他操作。**

## 三、以后更新信息

流程完全相同，只是第 2–3 步变成：打开你自己的 `_data/members/<你的id>.json` → 点右上角 ✏️ 编辑 → 修改 → 提交 PR。

> 毕业/离组时请把 `role` 改为 `"alumni"`，并填写 `destination`（去向），信息会自动移到"毕业校友"区。

## 四、字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 与文件名一致，小写连字符 |
| `name` / `name_zh` | ✅ | 英文名 / 中文名（网站中英切换时分别显示） |
| `role` | ✅ | `phd` 博士生 / `master` 硕士生 / `alumni` 校友（`pi` 仅负责人） |
| `since` | ✅ | 入学年份，整数，如 `2025` |
| `research` / `research_zh` | ✅ | 研究方向，中英各一句 |
| `photo` | ⬜ | 照片路径，如 `assets/people/san-zhang.jpg`（正方形、边长 ≥400px、≤300KB）；留空显示首字母头像 |
| `email` | ⬜ | 邮箱，填写后名字下方显示邮件图标 |
| `links.scholar` | ⬜ | Google Scholar 主页完整链接 |
| `links.github` / `links.gitlab` | ⬜ | GitHub / GitLab 主页链接 |
| `links.orcid` | ⬜ | ORCID 链接 |
| `links.homepage` | ⬜ | 个人主页链接 |
| `bio` / `bio_zh` | ⬜ | 一句话简介 |
| `destination` / `destination_zh` | 校友必填 | 毕业去向 |

## 五、常见问题

**Q: 提交 PR 时提示要 fork，正常吗？**
正常。没有仓库写权限时 GitHub 会自动在你账号下创建一个副本，审批合并的流程不受影响。

**Q: Checks 显示红色 ❌ 怎么办？**
点进 Details 查看具体错误（通常是 JSON 里少了逗号/引号，或必填字段为空），按提示修改后重新提交即可。

**Q: 我可以帮别人改吗？**
可以，但建议本人提交，管理员审批时会核对。

**Q: 审批多久能完成？**
管理员会收到 GitHub 邮件和网页通知，一般 1–2 天内。着急可在组群里提醒。

**Q: 我不想提 PR，可以请管理员代劳吗？**
可以。把上述信息按模板填好发给管理员即可，由管理员直接提交。
